# PRD: setup.sh による環境導入

- 種別: 既存の実装から逆生成した PRD
- 調査の基準コミット: `3400bcc`
- 読者: PdM、開発者、QA担当、CS担当

## 問題と根拠

手作業の環境構築は再現できない。
WSL と macOS の複数マシンで開発環境を手作業で揃えると、マシン間で設定がずれ、手順も漏れる。
壊れた環境の復旧にも時間がかかる。

同じリポジトリを WSL と macOS の両方に展開できるようにした変更（be5481f）と、復旧時や低スペックのマシンで使えるシェルが得られるまでの待ち時間を問題とした変更（df84b4b）が、この問題を裏付ける。

## 対象となる利用者

このリポジトリの所有者本人だけを対象とする。
所有者は自分の WSL（NixOS）マシンと macOS マシンの開発環境を整える。

## 提供する価値

利用者は、1つのコマンドで既存マシンと同じ開発環境を再現できる。

## 業務要求・機能要求

1. 利用者はプロファイル（`full` または `minimal`）を指定して1つのコマンドを実行し、そのプロファイルの環境を展開できる。
   - `full` は日常的に使う全機能を含む。
   - `minimal` はシェル、Git、Claude Code、Node.js、基本的な CLI ツールだけを含む。
2. 利用者が OS を意識せずに済むよう、macOS、NixOS（WSL を含む）、それ以外の Linux のどれかを判定し、その OS に合った方法で展開する。
3. プロファイルが指定されていない場合と、`full` と `minimal` のどちらでもない場合は、何も展開しない。使い方を表示して異常終了する。
4. リポジトリの Nix 設定で、利用者の既存の Nix 設定を置き換える。何度実行しても同じ状態になる。
5. 各段階の進捗を表示する。完了時に、シェルの再起動を利用者に案内する。

## 対象外

- Nix 本体の導入。flakes を有効にした Nix が導入済みであることを前提条件とする。
- 所有者と異なるユーザー名、ホスト名、リポジトリの配置先での実行。

## 成功条件

新規のマシンまたは復旧したマシンで、既存マシンと同じ環境が得られる。
その際、前提条件の導入とコマンドの実行以外に手作業を必要としない。
数値目標は設けない。

## 受入条件

1. `full` と `minimal` のそれぞれで、macOS、NixOS、それ以外の Linux の構成をビルドできる。
2. プロファイルが指定されていない場合と不正な値の場合は、何も展開せずに異常終了する。
3. 再実行しても同じ状態になる。
4. 完了時に、シェルの再起動を案内する。

基準コミット時点で CI が自動で確かめているのは、1 のビルド可否だけである（ドライラン）。
2 から 4 の自動テストはない。
