# PRD: 開発環境の導入

所有者が、1回の操作でどのマシンにも同じ開発環境を導入できるようにするための要求と受入条件を定める。

- 読者: PdM、開発者、QA担当、CS担当

## 問題

開発環境を手作業で構築すると、同じ環境を再現できない。
所有者は WSL（Windows 上で Linux を動かす機能）と macOS の複数マシンを使っており、手作業で揃えるとマシン間で設定がずれ、手順も漏れる。
壊れた環境の復旧にも時間がかかる。

## 対象となる利用者

リポジトリの所有者本人だけを対象とする。

## 提供する価値

所有者は、1回の操作で既存マシンと同じ開発環境を再現できる。

## 要求と受入条件

所有者は、導入する範囲を次の2つから選ぶ。

| 導入範囲 | 含むもの |
|---|---|
| すべて | 日常的に使う開発環境の全体 |
| 最小限 | シェル、Git、Claude Code、Node.js、基本的なコマンドラインツール |

「最小限」は、壊れた環境でもすぐに作業を始められるようにするための範囲である。

各要求と、その要求を受け入れる条件は次のとおり。

| # | 要求 | 受入条件 |
|---|---|---|
| 1 | 導入範囲を選び、1回の操作でその範囲を導入できる | 2つの導入範囲それぞれで導入できる |
| 2 | macOS、WSL、それ以外の Linux で同じ操作で導入できる | 3種類の OS と2つの導入範囲の6通りで導入できる |
| 3 | 導入範囲の指定を誤った場合は何も導入しない | 未指定と未定義の値で、何も導入せずにエラーで終わる |
| 4 | 何度導入しても同じ状態になる | 導入済みのマシンで再度導入しても、状態が変わらない |
| 5 | 導入中の進み具合と、完了後にすることを示す | 完了時に、シェルの再起動を案内する |

要求3でエラーになった場合は、正しい指定方法を示す。

## 対象外

- 導入操作の前提となるツールの準備。所有者が事前に済ませておく。
- 所有者と異なるユーザー名、マシン名、リポジトリの配置先での導入。
- WSL で使う端末アプリの設定を、Windows 側へ配置すること。所有者が手作業で配置する。
- macOS で、Claude Code から操作するブラウザを導入すること。所有者が手作業で導入する。

## 成功条件

新規のマシンまたは復旧したマシンで、前提となるツールの準備と導入操作のほかに手作業をせず、既存マシンと同じ環境が得られる。対象外に挙げた作業は、この手作業に含めない。
数値目標は設けない。
