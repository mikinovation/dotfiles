# PRD: 開発環境の導入

- 読者: PdM、開発者、QA担当、CS担当

## 問題と根拠

開発環境を手作業で構築すると、同じ環境を再現できない。
WSL と macOS の複数マシンで環境を揃えようとすると、マシン間で設定がずれ、手順も漏れる。
壊れた環境の復旧にも時間がかかる。

## 対象となる利用者

リポジトリの所有者本人だけを対象とする。
所有者は、自分の WSL マシンと macOS マシンの開発環境を整える。

## 提供する価値

利用者は、1回の操作で既存マシンと同じ開発環境を再現できる。

## 業務要求・機能要求

1. 利用者は、導入する範囲を「すべて」と「最小限」のどちらかから選び、1回の操作でその範囲の環境を導入できる。
   - 「すべて」は、日常的に使う環境の全体を含む。
   - 「最小限」は、シェル、Git、Claude Code、Node.js、基本的なコマンドラインツールだけを含む。
2. 利用者は、macOS、WSL、それ以外の Linux のどれでも、同じ操作で導入できる。
3. 導入範囲を選んでいない場合と、定義されていない範囲を指定した場合は、何も導入しない。正しい指定方法を示してエラーで終える。
4. 何度導入しても、同じ状態になる。
5. 導入中は、各段階の進み具合を利用者に示す。完了時には、環境を反映するためにシェルを再起動するよう案内する。

## 対象外

- 導入操作の前提となるツールの準備。利用者が事前に済ませておく。
- 所有者と異なるユーザー名、マシン名、リポジトリの配置先での導入。

## 成功条件

新規のマシンまたは復旧したマシンで、既存マシンと同じ環境が得られる。
その際、前提となるツールの準備と導入操作のほかに、手作業を必要としない。
数値目標は設けない。

## 受入条件

1. 「すべて」と「最小限」のそれぞれで、macOS、WSL、それ以外の Linux に環境を導入できる。
2. 導入範囲を選んでいない場合と、定義されていない範囲を指定した場合は、何も導入せずにエラーで終わる。
3. 再度導入しても、同じ状態になる。
4. 完了時に、シェルの再起動を案内する。
