# PRD: エディターの導入

所有者が、開発環境を導入するだけで、どのマシンでも同じ操作で使えるエディターを得られるようにするための要求と受入条件を定める。

- 読者: 開発者

この PRD の用語は次の意味で使う。

- 既定のエディター: ほかのツールが文章の入力を求めるときに開くエディター。
- 「すべて」「最小限」: PRD 0001「開発環境の導入」で定める導入範囲。
- WSL: Windows 上で Linux を動かす機能。

## 問題

エディターと、言語ごとの補完や診断をマシンごとに手作業で揃えると、マシン間で設定がずれる。
その結果、補完や診断を使えないマシンが生じる。
また、エディターだけで開発作業を終えられないと、Git の操作、テスト、データベースの操作などのたびに別のアプリへ切り替えることになり、作業が途切れる。

## 対象となる利用者

リポジトリの所有者本人だけを対象とする。

## 提供する価値

所有者は、「すべて」を導入するだけで、既存マシンと同じ操作で編集を始められる。
使う言語の補完、診断、整形も、導入した時点で使える。
開発作業の多くを、エディターを離れずに終えられる。

## 要求と受入条件

各要求と、その要求を受け入れる条件は次のとおり。

| # | 要求 | 受入条件 |
|---|---|---|
| 1 | 導入したエディターを既定のエディターとして使える | 既定のエディターを開く操作で、導入したエディターが起動する |
| 2 | 初回起動時に、編集機能が自動で揃う | 初回起動で、所有者が操作せずに編集機能が揃う |
| 3 | 起動時にエラーが出ない | 2回目以降の起動で、エラーが表示されない |
| 4 | 日常的に使う言語で、補完と診断を使える | 対象言語のファイルで、補完と診断が表示される |
| 5 | 定義への移動と名前の変更を使える | 対象言語のファイルで、定義へ移動し名前を変更できる |
| 6 | コードを整形できる | 言語側が整形に対応している場合だけ、整形できる |
| 7 | ファイル名や文字列でファイルを探せる | 名前と文字列のどちらでもファイルを探せる |
| 8 | ファイルの一覧をツリーで表示できる | エディター内でファイルのツリーを開ける |
| 9 | Git の日常的な操作をエディター内で行える | 状態確認、コミット、差分、履歴を表示できる |
| 10 | Git のコンフリクトをエディター内で解消できる | コンフリクト箇所で、どちらの変更を採るか選べる |
| 11 | GitHub の Issue と PR をエディター内で扱える | エディター内で Issue と PR を表示できる |
| 12 | テストをエディター内で実行できる | カーソル位置のテストと、ファイル内の全テストを実行できる |
| 13 | データベースをエディター内で操作できる | エディター内でデータベースに問い合わせられる |
| 14 | HTTP リクエストをエディター内で送れる | エディター内でリクエストを送り、応答を表示できる |
| 15 | エディター内で端末を開ける | エディターを閉じずに端末を開閉できる |
| 16 | メモとタスクを作業状態ごとに管理できる | タスクに作業状態を付け、状態ごとに一覧できる |
| 17 | AI の入力補完を使える | 入力中に AI の補完候補が表示される |
| 18 | AI にファイルや選択範囲を送れる | ファイルと選択範囲を、エディターから AI へ送れる |
| 19 | エディターと OS のクリップボードを共有できる | WSL と macOS で、双方向にコピーと貼り付けができる |
| 20 | 同じキーに複数の操作を割り当てない | 同じキーに割り当てた操作が1つだけである |

要求2の初回起動には、ネットワークへの接続が必要である。

## 対象外

- 「最小限」の導入範囲でエディターを導入すること。
- WSL 以外の Linux で、エディターと OS のクリップボードを共有すること。
- ネットワークに接続していない状態での初回起動。
- エディターから呼び出す外部ツールのうち、一部のツールの導入。所有者が、そのツールを使う前に手作業で導入する。

## 成功条件

新規のマシンまたは復旧したマシンで「すべて」を導入したあと、手作業で設定せずに、既存マシンと同じ操作で編集を始められる。
数値目標は設けない。
