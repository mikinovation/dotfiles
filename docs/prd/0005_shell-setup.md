# PRD: シェル環境の導入

所有者が、シェルでのコマンド入力とディレクトリ移動を少ない手数で行えるようにするための要求と受入条件を定める。

- 読者: PdM、開発者、QA担当、CS担当
- 段階: 5. デリバリー（要求と受入条件を確定し、実装済み）

この PRD の用語は次の意味で使う。

- 対象のシェル: この PRD で設定するシェル。ほかのシェルは設定しない。
- 非対話の実行: 人が入力せず、スクリプトや AI エージェントがコマンドを動かすこと。
- 「すべて」「最小限」: PRD 0001「開発環境の導入」で定める導入範囲。
- WSL: Windows 上で Linux を動かす機能。

## 課題

### 問題と根拠

設定を加えていないシェルでは、コマンド入力とディレクトリ移動に手数がかかる。
所有者はよく使うコマンドを毎回最後まで打ち、過去に打ったコマンドを探すためにキーを何度も押して履歴を遡る。
深い階層のディレクトリへは、移動を何度も重ねる。
直前のコマンドが失敗しても気付かないまま、次の操作へ進むこともある。
加えて WSL では、シェルでコピーした内容が Windows 側と行き来しない。両者を移動するたびに、元の場所へ戻って再びコピーすることになる。

### 対象となる利用者

リポジトリの所有者本人だけを対象とする。
非対話の実行は利用者ではない。ただし、対話のために加えた機能がその実行を壊さないことは要求に含める。

### 提供する価値

所有者は、短い入力と少ない操作でコマンドを打ち、過去に打ったコマンドと過去に訪れたディレクトリへ戻れる。
直前のコマンドが成功したかを見て判断できる。
WSL では、シェルでコピーした内容を Windows 側とやり取りできる。
この機能は、「すべて」「最小限」のどちらを導入しても使える。

### 対象外

- 対象のシェル以外のシェルで、同じ操作を使えるようにすること。
- 所有者以外のユーザーに合わせた設定。
- WSL 以外の Linux で、シェルと OS のクリップボードを共有すること。
- シェルで使うコマンドラインツールそのものの入手。PRD 0001「開発環境の導入」で扱う。
- 端末アプリそのものの設定と、画面の分割。PRD 0003「端末多重化ツールの導入」で扱う。

### 制約とトレードオフ

所有者は、次のことを受け入れる。

- シェルの入力補助の版は、そのマシンで初めてシェルを開いた時点のもので止まり、マシン間で揃わない。PRD 0001「開発環境の導入」の「何度導入しても同じ状態になる」を、入力補助については満たさない。
- 初めてシェルを開くときにネットワークへの接続が必要になる。接続できなければ、プロンプトと入力補助を使えない。
- 短い綴りの展開、履歴の絞り込み、WSL のクリップボード連携は、リポジトリを決まった場所に置くことを前提とする。リポジトリを移動すると、これらは知らないうちに使えなくなる。
- プロンプトのアイコン表示には、アイコンに対応したフォントを端末側で用意する必要がある。
- 非対話の実行を壊さないため、通常のディレクトリ移動のコマンドは置き換えない。名前の一部での移動は、別の短い入力で行う。

### 成功条件

所有者が、よく使うコマンドとディレクトリ移動を、設定を加えていないシェルより少ない文字数と操作回数で行える。
導入したあと、追加の設定や手作業をせずにシェルでの作業を始められる。
数値目標は設けない。

### 計測と学習の計画

新規のマシンへの導入と、壊れたマシンの復旧のたびに、成功条件を満たしたかを確かめる。
手作業の設定や不具合が生じた場合は記録し、要求と対象外を見直す材料にする。

## 解決策

### 要求と受入条件

各要求と、その要求を受け入れる条件は次のとおり。

| # | 要求 | 受入条件 |
|---|---|---|
| 1 | ログイン時に、対象のシェルが最初から開く | WSL、macOS、それ以外の Linux で、端末を開くと対象のシェルが動く |
| 2 | シェルを開いてすぐ入力を始められる | 端末を開いた直後にプロンプトが出て、入力を受け付ける |
| 3 | 現在のディレクトリと Git の状態を常に見られる | リポジトリ内ではディレクトリ、ブランチ、変更の有無が出る。リポジトリ外ではディレクトリだけ出る |
| 4 | 直前のコマンドの失敗と、長くかかった処理の所要時間が分かる | 失敗した直後に入力記号の色が変わり、一定時間を超えると所要時間が出る |
| 5 | よく使うコマンドを短い綴りで打てる | 版管理、コンテナ操作、エディターで、短い綴りが完全なコマンドに展開される |
| 6 | 入力中に、過去に打ったコマンドの続きが提示される | 打ち始めた文字に続く候補が薄く出て、そのまま採用できる |
| 7 | コマンドの構文が色で区別される | 存在するコマンドと存在しないコマンド、引数、文字列を色で区別する |
| 8 | コマンドと引数を補完できる | コマンド名、引数、ファイル名を補完できる |
| 9 | 別のシェルで打ったコマンドも履歴から呼び出せる | 一方のシェルで打ったコマンドを、別に開いたシェルで呼び出せる |
| 10 | 履歴を絞り込んで選んで実行できる | 絞り込んで選ぶと実行され、その実行が履歴に残る。同じコマンドは1件にまとめる |
| 11 | ディレクトリ名を打つだけで移動でき、過去に訪れた場所は名前の一部でも移動できる | 移動コマンドを付けずに名前だけで移動でき、訪れた場所は名前の一部でも移動できる |
| 12 | 上の階層と、直前まで居たディレクトリへ短い入力で戻れる | 階層の数に応じた短い入力で上へ移動し、直前のディレクトリへ戻れる |
| 13 | シェルでコピーした内容を Windows 側とやり取りできる | WSL で、シェルからコピーした内容を Windows 側に貼り付けられ、その逆もできる |
| 14 | シェルに加えた機能が、非対話の実行を壊さない | 非対話で実行したコマンドが、対話用の機能を理由に失敗しない |

要求1は、すでに対象のシェルが開くマシンでは何も変えない。
要求13は WSL だけを対象とする。

### 成功条件の測定方法

新規のマシンまたは復旧したマシンに導入したとき、所有者が受入条件を手作業で一つずつ確かめる。
あわせて、導入のほかに手作業の設定が要ったかを確かめる。
計測の仕組みは設けない。

### 展開計画

所有者のマシンだけに提供する。
段階的な公開はしない。
変更は、各マシンで導入操作をやり直した時点で、そのマシンに反映される。
