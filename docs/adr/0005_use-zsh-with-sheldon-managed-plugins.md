# ADR: シェルに zsh を使い、プラグインを sheldon で管理する

シェルとして zsh を採用し、設定を Home Manager で生成し、プラグインの取得を sheldon に任せるという決定を記録する。

- 読者: 技術責任者、開発者、将来の保守者
- 状態: 採用
- 決定日: 2026-09-27

用語は PRD 0005 と同じ意味で使う。
非対話の実行は、人が入力せず、スクリプトや AI エージェントがコマンドを動かすことを指す。
「すべて」「最小限」は、PRD 0001 が定める導入範囲を指す。

## 背景

PRD 0005 は、設定を加えていないシェルでの手数を問題として挙げる。
所有者はよく使うコマンドを毎回最後まで打ち、過去に打ったコマンドを探して履歴を遡り、深い階層のディレクトリへは移動を重ねる。
直前のコマンドが失敗しても気付かないまま、次の操作へ進むことがある。
WSL では、シェルでコピーした内容が Windows 側と行き来しない。

所有者は Nix を導入する前から zsh を使い、プラグインを sheldon で管理していた。
ADR 0001 の決定により環境を Home Manager へ移したとき、この設定を宣言的に書き直した。
シェルとプラグイン管理の新規選定ではなく、既存の設定の引き継ぎが出発点である。

ADR 0004 で導入した Claude Code をはじめ、エージェントとスクリプトは非対話でこのシェルを呼ぶ。

## 制約

PRD 0005 の要求から、選べる案は次の条件を満たす必要がある。

- WSL、macOS、それ以外の Linux で、ログイン時に対象のシェルが開き、開いた直後に入力を受け付ける。
- 現在のディレクトリ、Git のブランチと変更の有無、直前のコマンドの失敗、長くかかった処理の所要時間を、プロンプトで見られる。
- よく使うコマンドを短い綴りで打て、入力中に過去のコマンドの続きが候補として出る。
- コマンドの構文が色で区別され、コマンド名と引数を補完できる。
- 別のシェルで打ったコマンドを履歴から呼び出せる。
- 履歴を絞り込んで選ぶとその場で実行され、その実行が履歴に残り、同じコマンドは1件にまとまる。
- ディレクトリ名だけで移動でき、過去に訪れた場所へは名前の一部で移動でき、上の階層と直前のディレクトリへ短い入力で戻れる。
- WSL で、シェルからコピーした内容を Windows 側に貼り付けられ、その逆もできる。
- 対話のために加えた機能が、非対話の実行を壊さない。とくに、対話用に上書きした組み込みコマンドを理由として、非対話で実行したコマンドが失敗しない。

導入については、PRD 0001 の要求と ADR 0001 の決定から、次の条件を満たす必要がある。

- 導入範囲「すべて」「最小限」の両方に含める。
- macOS、WSL、それ以外の Linux で同じ手順で導入できる。
- 導入するものの版を固定し、何度導入してもどのマシンでも同じ状態になる。
- 導入後に手作業で設定しなくても使える。

## 決定

シェルとして zsh を採用し、設定は ADR 0001 の共通の Home Manager 設定から生成する。
導入範囲は「すべて」「最小限」の両方に含める。

- 既定シェルにする仕組みは OS ごとに分ける。NixOS と macOS では、それぞれ NixOS と nix-darwin が持つユーザーのシェル設定で指定する。それ以外の Linux では、Home Manager の activation が `/etc/shells` へ追記して `chsh` を実行する。
- プラグインの取得は sheldon に任せる。Home Manager が `plugins.toml` を配置し、そこには GitHub のリポジトリ名だけを書いて版を指定しない。読み込むのは oh-my-zsh、Powerlevel10k、zsh-autosuggestions、zsh-syntax-highlighting、zsh-completions、zsh-abbr、zsh-defer とする。
- プロンプトは Powerlevel10k とする。instant prompt を有効にし、Home Manager が `.p10k.zsh` を配置し、設定ウィザードは環境変数で止める。プロンプトにはディレクトリ、Git の状態、直前の終了コード、3秒を超えた処理の所要時間を出す。
- 短縮入力は zsh-abbr で行い、git、docker、nvim の綴りを定義する。ディレクトリ移動は zoxide を使う。
- 履歴の絞り込みは自前の zsh 関数 `cmi` で行う。`fc` が返す履歴から重複を1件にまとめて fzf で選ばせ、選んだコマンドを履歴へ残してから実行する。
- 履歴の共有と階層移動には設定を書かず、Home Manager の既定（`SHARE_HISTORY` ほか）と oh-my-zsh の既定（`auto_cd`、`...` 系のグローバルエイリアス）に任せる。
- `.zshenv` に PATH と fnm の設定を置き、`.zshrc` に対話用の読み込みを置く。zoxide は対話シェルでは `cd`、非対話シェルでは `z` として初期化する。
- WSL のクリップボード連携とロケールは `wsl.zsh` に分け、`/proc/version` を見て WSL でだけ有効にする。クリップボードの読み書きには `clip.exe` と `powershell.exe` を使う。

## 決定理由

- zsh は、所有者が持つ既存の設定（oh-my-zsh、Powerlevel10k、zsh-abbr）をそのまま使えるため、書き直しの手間なしに PRD 0005 の要求を満たせる。
- zsh は POSIX 互換であり、`fnm env` や `direnv hook` のように sh 系シェルを前提とする出力を、そのまま評価できる。
- 既定シェルを管理する主体は OS ごとに違うため、その主体に合わせて仕組みを分ける。
- sheldon は既存の `plugins.toml` をそのまま使えるため、プラグインの管理を書き直す手間がかからない。
- Powerlevel10k は instant prompt を持ち、プラグインの読み込みを待たずにプロンプトを出せるため、開いた直後に入力を受け付けるという制約を満たせる。
- 自前の関数 `cmi` は、選んだコマンドをその場で実行して履歴へ残し、同じコマンドを1件にまとめる。この2点が履歴の絞り込みに関する制約そのもので、既存のウィジェットでは満たせない。
- zoxide と fzf は Home Manager のモジュールを使わず手書きで初期化する。対話では `cd` を置き換え、非対話では `z` にする必要があり、モジュールが生成する1行の初期化では書き分けられない。
- zsh-abbr は入力行に完全なコマンドを展開するため、実行前に内容を確認でき、履歴にも完全な形で残る。
- `clip.exe` と `powershell.exe` は WSL に最初からあるため、追加の入手がいらず、導入後の手作業なしでクリップボードを共有できる。
- PATH と fnm の設定を `.zshenv` に置くのは、非対話の実行でも fnm が管理する Node.js を使うためである。

## 代替案

次の案は、それぞれの理由で採らない。

- fish: 独自の構文を持つため、`fnm env` や `direnv hook` のように sh 系シェルを前提とする出力をそのまま評価できず、既存の zsh の設定も使えない。
- bash: 移行の手間は小さいが、候補の提示、構文の着色、補完に関する制約を満たすプラグインが、zsh ほど揃っていない。
- Home Manager のプラグイン設定: nixpkgs のパッケージを使うため `flake.lock` で版を固定でき、必要なプラグインも nixpkgs に揃っている。版の固定という点では優れるが、既存の `plugins.toml` を書き直す必要があり、その手間に見合わない。
- starship: 3 OS で同じ設定を使え、Nix で版も固定できる。ただし instant prompt に当たる仕組みがなく、開いた直後に入力を受け付けるという制約を満たしにくい。
- fzf が持つ `Ctrl-R` の履歴ウィジェット: 選んだコマンドを入力行に置くだけで実行せず、重複もまとめないため、履歴の絞り込みに関する制約を満たせない。
- atuin: 別の履歴データベースを持ち込むため、zsh の履歴ファイルを共有する仕組みと二重になる。
- エイリアス: 入力行に展開されないため、履歴には短い綴りのまま残り、後から何を実行したか分からない。
- win32yank: WSL のクリップボードを共有できるが、別途バイナリを配置する必要があり、導入後に手作業なしで使えるという制約を満たせない。

## 結果

- プラグインの版は、そのマシンで初めてシェルを開いた時点のもので止まる。更新する仕組みもないため、マシン間で版が揃わない。ADR 0001 が挙げた版の固定と冪等性を、プラグインについては満たしていない。
- 初めてシェルを開くとき、sheldon が GitHub から取得するためネットワークが必要になる。取得できなければプロンプトと入力補助が使えない。
- 環境変数 `ZSH` は sheldon の取得先を指す。`plugins.toml` から oh-my-zsh を外すと、この変数が無効なパスを指し、`auto_cd` と `...` 系のエイリアスによる階層移動も失われる。
- 履歴の共有は Home Manager の既定に依存する。その既定が変われば、別のシェルで打ったコマンドを呼び出せる状態が、知らないうちに失われる。
- `abbr.zsh`、`fzf.zsh`、`wsl.zsh` は Home Manager が配置せず、`DOTFILES_DIR` が指すリポジトリのパスから読み込む。リポジトリをこのパスに置かないと、短縮入力、履歴の絞り込み、WSL のクリップボード連携が、知らないうちに失われる。
- Powerlevel10k のアイコン表示は Nerd Font を前提とするが、リポジトリは Nerd Font を入れていない。端末を動かす側で用意する必要がある。
- `.p10k.zsh` は1843行のウィザード生成物をリポジトリで管理しており、手で読み書きする前提ではない。
- zsh の設定には lint もテストもないため、変更の確認は手作業になる。
- 非対話のシェルでは `cd` が zoxide に置き換わらないため、エージェントとスクリプトの手順で `cd` をそのまま使える。代わりに、非対話では名前の一部での移動が `z` になる。
- 導入範囲「最小限」でも zsh、sheldon、zoxide、fzf が入り、同じ操作を使える。fnm は「すべて」にだけ入るが、`.zshenv` の fnm の設定は存在を確かめてから動くため、「最小限」でもエラーにならない。
