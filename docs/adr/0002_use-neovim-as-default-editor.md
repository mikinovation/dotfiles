# ADR: Neovim を既定エディターにする

Neovim を既定エディターにし、本体、設定、周辺ツールを Home Manager で管理するという決定を記録する。

- 読者: 技術責任者、開発者、将来の保守者
- 状態: 採用
- 決定日: 2026-09-28

## 背景

所有者は端末とシェルを中心に作業するため、端末内で動くエディターが必要である。
所有者は Vim 系のモード型の操作に慣れている。AI による支援には、端末で動く Claude Code を使う。
また、エディターは PRD 0001 の導入範囲「すべて」に含まれる日常の開発環境の一部であり、どのマシンでも同じエディター環境を使えるようにする必要がある。

## 制約

PRD 0001 の要求から、選べる案は次の条件を満たす必要がある。

- macOS、WSL、それ以外の Linux で同じ操作で導入できる。
- 何度導入しても同じ状態になる。
- 導入範囲「最小限」は、シェル、Git、Claude Code、Node.js、基本的なコマンドラインツールに限り、エディターを含めない。

## 決定

Neovim を既定エディターにする。
Neovim は ADR 0001 の共通の Home Manager 設定から、`nix/programs/neovim` のモジュールとして導入し、導入範囲「すべて」にだけ含める。

- 環境変数 `EDITOR` と `VISUAL` を `nvim` にし、`vi`、`vim`、`vimdiff` を Neovim の別名にする。
- 設定は Lua で書き、Home Manager が `~/.config/nvim` に配置する。
- 言語サーバー、formatter、linter、tree-sitter のパーサーのビルドに使うツールは、Neovim の追加パッケージとして Nix で導入する。
- プラグインは lazy.nvim で管理し、版をリポジトリの `lazy-lock.json` で固定する。

## 決定理由

- 端末内で動くため、端末中心の作業に合い、macOS、WSL、それ以外の Linux の端末から同じ操作で使える。
- 本体、設定、周辺ツールを Home Manager で宣言できるため、どの OS でも同じ版と同じ設定になり、何度導入しても状態が変わらない。
- 設定を Lua で書くため、luacheck と busted で設定を検証できる。
- 言語サーバーのクライアントと tree-sitter を内蔵しており、プラグインも豊富なため、補完、デバッグ、テストの実行をエディター内で行える。

## 代替案

次の案は、それぞれの理由で採らない。

- VS Code: 端末の外で動くため、端末中心の作業に合わない。
- Cursor: 次の2点から採らない。
  - 端末の外で動くため、端末中心の作業に合わない。
  - AI による支援は端末で動く Claude Code で賄うため、エディターに組み込まれた AI 機能を必要としない。
- Vim: 設定を Lua で書けないため、luacheck や busted で設定を検証できない。
- Emacs: 所有者は Vim 系のモード型の操作を使いたいが、Emacs でその操作を使うには evil などのプラグインが必要になる。
- IntelliJ IDEA: 次の2点から採らない。
  - 端末の外で動くため、端末中心の作業に合わない。
  - 設定を IDE の中で変更するため、宣言的に管理しにくい。

## 結果

- 導入範囲「最小限」の環境には Neovim が入らず、`EDITOR` も設定されない。
- プラグインは Nix ではなく lazy.nvim が初回起動時に取得する。版を固定する `lazy-lock.json` はリポジトリ内のものを参照するため、リポジトリを `~/dotfiles` に置く必要がある。
- 言語サーバーなどの周辺ツールのうち nixpkgs にないものは、自前のパッケージとして定義し、保守する。
