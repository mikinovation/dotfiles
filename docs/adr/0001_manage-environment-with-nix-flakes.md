# ADR: 開発環境を Nix flakes で宣言的に管理する

開発環境の導入と管理に Nix flakes を使い、OS ごとの仕組みから共通の Home Manager 設定を適用するという決定を記録する。

- 読者: 技術責任者、開発者、将来の保守者
- 状態: 採用
- 決定日: 2026-09-27

## 背景

開発環境を手作業で構築すると、同じ環境を再現できない。
所有者は WSL と macOS の複数マシンを使っており、手作業で揃えるとマシン間で設定がずれ、手順も漏れる。
壊れた環境の復旧にも時間がかかる。

## 制約

PRD 0001 の要求から、選べる案は次の条件を満たす必要がある。

- macOS、WSL、それ以外の Linux で同じ操作で導入できる。
- 導入範囲を「すべて」と「最小限」から選べる。
- 導入範囲の指定を誤った場合は何も導入しない。
- 何度導入しても同じ状態になる。
- 対象は所有者本人だけであり、所有者と異なるユーザー名、マシン名、リポジトリの配置先には対応しない。

## 決定

`nix/flake.nix` の1つの flake で、すべての OS の環境を定義する。
ユーザー環境は共通の Home Manager 設定（`nix/home.nix`）で定義し、OS ごとに次の仕組みから適用する。

| OS | 適用する仕組み | flake の出力 |
|---|---|---|
| WSL | NixOS-WSL の NixOS に、Home Manager をモジュールとして組み込む | `nixosConfigurations` |
| macOS | nix-darwin に、Home Manager をモジュールとして組み込む | `darwinConfigurations` |
| それ以外の Linux | Home Manager を単体で使う | `homeConfigurations` |

導入範囲ごとに別の出力を定義し、「最小限」の出力には `-minimal` を付ける。

## 決定理由

- 1つの flake と共通の Home Manager 設定を3つの OS で使うため、どの OS でも同じユーザー環境になる。
- `flake.lock` が依存の版を固定するため、どのマシンでも同じ版で導入できる。
- Nix は宣言した状態を適用するため、導入済みのマシンで再度導入しても状態が変わらない。
- 導入範囲を flake の別の出力として定義できるため、導入範囲の選択を出力名の選択として扱える。

## 代替案

次の案は採らない。

| 案 | 採らない理由 |
|---|---|
| シェルスクリプトと symlink | ツールの版の固定と、何度導入しても同じ状態になることを、自前のスクリプトで保証する必要がある |
| OS 標準のパッケージマネージャーと chezmoi などの dotfiles 管理ツール | Homebrew や apt など OS ごとに導入手順が分かれ、ツールの版をマシン間で揃えられない |
| Ansible | 状態ではなく手順を記述するため、パッケージの版の固定は OS のパッケージマネージャーに依存する |
| Dev Container や Docker | 開発環境をコンテナ内に閉じるため、ホストのシェルや設定ファイルを管理できない |
| mise | ランタイムやツールの版は管理できるが、設定ファイルと OS の設定は管理できない |

## 結果

- 導入操作の前に、Nix 本体を所有者が導入しておく必要がある。
- ユーザー名とマシン名を flake の出力に書くため、所有者と異なるユーザー名やマシン名では導入できない。
- nixpkgs は unstable を追う。`flake.lock` の更新は Renovate に任せる。
- nixpkgs にないツールは、`nix/pkgs/` で自前のパッケージとして定義し、保守する。
- WSL で使う端末アプリの設定を Windows 側へ配置する作業と、macOS で Claude Code から操作するブラウザの導入は、Nix の管理外として手作業で行う。
