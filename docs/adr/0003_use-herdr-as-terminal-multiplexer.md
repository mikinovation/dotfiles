# ADR: 端末多重化ツールに herdr を使う

端末多重化ツールとして herdr を採用し、設定を Home Manager で管理し、Neovim から herdr のエージェントへ送る仕組みを自前で実装するという決定を記録する。

- 読者: 開発者
- 状態: 採用
- 決定日: 2026-07-04

用語は PRD 0003 と同じ意味で使う。
エージェントは、指示を受けてコードを書き換える AI のプログラムのうち、端末の中で動かすものを指す。
端末多重化ツールは、一つの端末画面を分割し、複数の作業を同時に表示して切り替えるツールを指す。
「すべて」「最小限」は、PRD 0001 が定める導入範囲を指す。

## 背景

PRD 0003 は、エージェントを複数同時に走らせるときの問題を挙げる。
どれが入力待ちでどれが作業中かを一度に見られないため、端末を順に切り替えて確かめることになり、手を入れるべきエージェントへの気付きが遅れる。
扱うプロジェクトが複数あると、プロジェクトごとの端末の行き来も増える。
エディターで開いているコードや指示をエージェントへ渡すたびに、手作業のコピーと貼り付けが挟まる。

所有者は端末とシェルを中心に作業し、ADR 0002 の決定により Neovim を端末の中で使う。

## 制約

PRD 0003 の要求のうち、エージェントの監視について、選べる案は次の条件を満たす必要がある。

- 複数のエージェントの状態を、切り替えずに一画面で把握できる。
- 手を入れるべきエージェントが一覧の上位に来る。
- 注目するエージェントを、1つの操作で全画面表示と元の配置に行き来できる。
- 一覧を出すサイドバーを1つの操作で開閉でき、畳むと画面を占有しない。

画面とタブの操作については、次の条件を満たす必要がある。

- 画面を縦横に分割し、上下左右の隣へ移動できる。
- タブを増やし、前後に切り替えられる。
- プロジェクト単位でタブをまとめ、まとまりを新規作成して前後に切り替えられる。
- 分割、移動、タブの操作を、一般的な端末多重化ツールと同じ指使いで行える。
- マウスでも操作できる。
- 画面から流れた過去の出力を、上限まで戻って読める。

エディターからの操作については、次の条件を満たす必要がある。

- 選択範囲、現在行、ファイルパス、自由入力のテキストを、動いているエージェントへ送れる。
- 送り先のエージェントが複数あるときだけ、送り先を選ばせる。
- 編集中のファイルの場所を作業場所として、名前を付けたエージェントを立ち上げ、隣の領域に並べられる。
- 動いているプロジェクトのまとまりを一覧し、選んだものへ切り替えられる。
- 送れない状態のときは理由が示され、何も起きない。操作の成否がエディター上で分かる。

導入については、PRD 0003 の対象範囲と、PRD 0001 の要求および ADR 0001 の決定から、次の条件を満たす必要がある。

- 導入範囲「すべて」にだけ含め、「最小限」には含めない。
- macOS、WSL、それ以外の Linux で同じ操作で導入できる。
- 何度導入しても同じ状態になる。
- 導入後に手作業で設定しなくても使える。

## 決定

端末多重化ツールとして herdr を採用する。
herdr は ADR 0001 の共通の Home Manager 設定から、flake input `github:ogulcancelik/herdr` として導入し、導入範囲「すべて」にだけ含める。

- 版は `flake.lock` で固定し、herdr が使う nixpkgs はリポジトリ共通の入力に合わせる。
- 設定は Home Manager が `~/.config/herdr/config.toml` に配置する。
- prefix は `ctrl+b` とし、画面の分割、ペイン間の移動、タブの操作は tmux と同じ指使いに合わせる。
- エージェントの監視は、注目するエージェントを全画面に広げる操作を主とし、優先度順に並ぶサイドバーを副とする。サイドバーは畳むと画面を占有しない。
- Neovim から herdr のエージェントへ送る仕組みは、herdr の CLI を呼ぶ `plugins/herdr/actions` として自前で実装する。選択範囲、現在行、ファイルパス、自由入力の送信と、エージェントの起動、ワークスペースの切り替えを行う。

## 決定理由

- エージェントの一覧、状態の表示、優先度順の並びを herdr 自身が持つため、監視に関わる制約を自前の実装なしで満たせる。
- ワークスペースでタブをプロジェクト単位にまとめられるため、プロジェクトをまたぐ行き来に関わる制約を満たせる。
- 分割、ペイン移動、タブ操作のキーを設定で変更でき、tmux と同じ指使いに合わせられる。
- CLI が1行の JSON を返すため、エージェントの一覧、送信、起動、ワークスペースの切り替えを外部から呼び出せ、エディターとの連携を組める。
- flake を提供しており、ADR 0001 の Home Manager 設定から宣言的に導入して版を固定できる。
- 既存の Neovim プラグインは、端末多重化ツールとして tmux と zellij にしか対応せず、herdr へ送る経路を持たない。そのため herdr の CLI を直接呼ぶモジュールを自前で書く。

## 代替案

次の案は、それぞれの理由で採らない。

- tmux: エージェントの一覧、状態の把握、優先度順の並びに当たる機能がない。監視に関わる制約を満たすには、ペインの一覧と状態の判定を自前で作る必要がある。
- zellij: 同じくエージェントの監視に当たる機能がない。エディターから送る仕組みは既存のプラグインが対応しているが、監視に関わる制約を満たせないため、その利点では覆らない。
- 端末エミュレータに内蔵された多重化機能: 次の2点から採らない。
  - エージェントの監視に当たる機能がない。
  - 多重化を端末エミュレータ側に置くと、その端末エミュレータでしか同じ操作にならない。
- 端末多重化ツールを使わず、エディターの端末ウィンドウだけで済ませる案: 次の2点から採らない。
  - 通常のシェル作業を同じ画面で行えない。
  - エージェントがエディターの寿命に縛られ、複数のプロジェクトをまたいで走らせ続けられない。

## 結果

- 導入範囲「最小限」の環境には herdr も設定も入らないため、エージェントの監視とエディターからの送信を使えない。
- herdr は nixpkgs になく flake から取得する Rust 製のため、バイナリキャッシュが効かない環境ではソースからのビルドになり、メモリの限られた環境では導入に時間がかかる。
- 版は `flake.lock` で固定するため、herdr の更新は lock の更新を通じてのみ行う。
- 自前のモジュールは herdr の CLI の出力形式に依存するため、herdr 側で CLI が変わると動かなくなる。テストは CLI の応答を固定値で置き換えており、実際の CLI との食い違いはテストでは分からない。
- エディターから立ち上げられるエージェントは claude に限られる。
- 多重化を herdr に置いたため、端末エミュレータ側のタブとペインの機能は使わない。
- 端末を閉じたあとの画面構成は復元されず、シェルの起動時に自動では立ち上がらない。
