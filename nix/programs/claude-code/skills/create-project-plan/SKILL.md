# create-project-plan: プロジェクト計画書作成ヒアリングスキル

PRD を起点に計画の材料を grilling で聞き取り、ユーザーの承認を得てから tanteki に執筆を渡す。このスキルは材料集めだけを行う。

## 手順

### 1. PRD を読む

保存済みの PRD ファイルのパスを受け取り、そのファイルとこれまでの会話だけを読む。リポジトリを自発的に探索しない。会話に貼られた PRD 本文や、未保存の草稿を入力として扱わない。

パスが示されていない場合は、聞き取りに入らず PRD の提示を求めて止まる。

### 2. 計画の対象範囲を確認する

PRD のどの要求を計画に載せるかをユーザーに決めさせる。PRD が複数の段階や版の要求を含む場合、今回の計画に載せる範囲は PRD から一意に決まらないため、PRD から導ける案を示した上で選ばせる。

計画に載せる要求が PRD に見当たらない場合は、聞き取りを続けず PRD の確定を求めて止まる。

### 3. PRD の欠落を提示する

計画に影響する欠落と `TBD` を一覧で示し、PRD を先に直すか、`TBD` を抱えたまま計画を進めるかをユーザーに選ばせる。独断で進めない。欠落した要求、成果物、条件を計画側で補わない。

PRD を先に直すと答えた場合は、聞き取りに入らず止まる。

### 4. 読者を確認する

計画書の読者は PM、開発、関係部署である。これを提示し、異なる読者を想定している場合だけ修正を求める。質問としては投げない。

### 5. grilling で材料を詰める

`Skill` ツールで `grilling` を呼び、次の9項目を材料とする。このうち質問の7項目を論点として順に詰める。

| # | 項目 | 何のために聞くか | 扱い |
|---|---|---|---|
| 1 | 計画の対象範囲 | どの要求を計画に載せるか | 手順2で確定 |
| 2 | 成果物 | 何を作れば要求を満たすか | 質問 |
| 3 | 節目 | どの時点で何が揃うか | 質問 |
| 4 | 担当 | 誰が各成果物を持つか | 質問 |
| 5 | 先行作業と前提条件 | 着手・完了に先立つ条件 | 質問 |
| 6 | リスク | 計画を崩す要因と兆候 | 質問 |
| 7 | 判断が必要な時期と条件 | 関係者が調整すべき分岐 | 質問 |
| 8 | 計画の対象外 | この計画で管理しない範囲 | 質問 |
| 9 | 出典 | 各主張の根拠となる原資料 | 転記 |

項目1は手順2で確定しているため、材料に載せるだけで詰め直さない。項目9の出典は PRD から埋め、埋めたことをユーザーに伝える。質問の7項目は、粒度と分割の判断が入るため、PRD から導ける案を示した上で必ず質問として投げる。

聞き取りの途中で PRD 以外の原資料が根拠として出た場合は、出典に追記する。体制、見積もり、会話での合意がこれに当たる。

grilling が求める推奨回答は、提案であることを明示して示す。ユーザーが承認するまで材料に書き込まない。回答にない事実、数値、条件を補わない。

節目の日付は、絶対日付、相対期間、順序のみのいずれでもよく、決まっていなければ `TBD` とする。各節目の完了条件は `TBD` を認めない。

項目4では、成果物ごとの担当を尋ねる前に、体制の人数と役割を確認する。担当はロールまたはチーム名を既定とし、人名は指定があった場合だけ使う。成果物ごとに担当を1つに絞り、複数併記を認めない。

体制が1人だと答えた場合は、担当の聞き取りをこの確認1回で打ち切り、全成果物に同じ担当を割り当てる。

ユーザーが決まっていないと答えた項目は、考えさせ続けずに `TBD` として次へ進む。ただし節目の完了条件が `TBD` のままでは計画が成立しないため、完了条件が定まるまで手順6へ進まない。節目が1件も定まらない場合も同様に、節目1件とその完了条件が定まるまで手順6へ進まない。

### 6. 材料一覧を提示して合意を取る

grilling の最終確認として、全9項目を一覧で示し、`TBD` の件数を併記する。この内容で計画書を書いてよいか確認し、承認を待つ。承認を二度に分けず、ここで得た承認をもって手順7へ進む。

### 7. tanteki に執筆を渡す

`Skill` ツールで `tanteki` を呼び、文書の種類がプロジェクト計画であること、区分が `flow` であること、確定した材料を渡して執筆させる。

## このスキルで扱わないこと

- 節構成、見出し、本文の表現
- textlint による検査と合格判定
- 計画書ファイルの保存先
- 工数見積もり、作業分解、ガントチャート等の図表生成
- 要求そのものの追加と変更（PRD の領分）
- 要求を満たす実現方式の選択（Design Doc、ADR の領分）
- 作成後の進捗更新と報告（進捗報告の領分）
- チケット起票、Git 操作、関係者への通知
