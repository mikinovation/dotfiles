# create-prd: PRD作成ヒアリングスキル

PRD の材料を grilling で聞き取り、ユーザーの承認を得てから tanteki に執筆を渡す。このスキルは材料集めだけを行う。

## 手順

### 1. 資料を確認する

ユーザーが示した資料と、これまでの会話だけを読む。リポジトリを自発的に探索しない。既存の記述から埋まる項目は、手順3で飛ばす。

### 2. 読者を確認する

PRD の読者は PdM、開発者、QA担当、CS担当である。これを提示し、異なる読者を想定している場合だけ修正を求める。質問としては投げない。

### 3. grilling で8項目を詰める

`Skill` ツールで `grilling` を呼び、次の8項目を論点として順に詰める。手順1で埋まっている項目は飛ばし、飛ばしたことをユーザーに伝える。

| # | 項目 | 何のために聞くか |
|---|---|---|
| 1 | 問題と根拠 | 要求が必要な理由を支える |
| 2 | 対象となる利用者 | 誰の問題かを定める |
| 3 | 提供する価値 | 関係者が何を得るかを示す |
| 4 | 業務要求・機能要求 | どの振る舞いで問題を解決するか |
| 5 | 対象外 | 要求の適用範囲を限る |
| 6 | 成功条件 | 要求が満たされたかを測定する基準 |
| 7 | 受入条件 | 受け入れを判断する基準 |
| 8 | 出典 | 各主張の根拠となる原資料 |

8項目はいずれもユーザーが決めることであり、調べて埋める事実ではない。grilling が求める環境の調査は手順1の範囲にとどめる。

grilling が求める推奨回答は、提案であることを明示して示す。ユーザーが承認するまで材料に書き込まない。回答にない事実、数値、条件を補わない。

ユーザーが決まっていないと答えた項目は、考えさせ続けずに `TBD` として次へ進む。

### 4. 材料一覧を提示して合意を取る

grilling の最終確認として、全8項目を一覧で示し、`TBD` の件数を併記する。この内容で PRD を書いてよいか確認し、承認を待つ。承認を二度に分けず、ここで得た承認をもって手順5へ進む。

### 5. tanteki に執筆を渡す

`Skill` ツールで `tanteki` を呼び、確定した材料を渡して PRD を執筆させる。

## このスキルで扱わないこと

- 節構成、見出し、本文の表現
- textlint による検査と合格判定
- PRD ファイルの保存先
- 要求を満たす実現方式の選択（Design Doc、ADR の領分）
- 作業の分担と進捗（計画、チケットの領分）
